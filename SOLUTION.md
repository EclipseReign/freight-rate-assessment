# Freight rate prediction solution

Start here. The supplied `readme.md`, `requirements.txt`, `score.py`, and all assessment inputs are preserved unchanged.

## Submission files

- `validation_predictions.csv`: exactly 12,000 rows, in the original template order; columns `load_id,predicted_rate`.
- `data/december_chart_inputs.csv`: completed 31-row December scenario, with all original inputs preserved.
- `scorer_results/candidate_december.png`: generated by the original scorer.
- `output/pdf/freight_rate_report.pdf`: English report with validation, data quality, methodology, limitations, and the required chart.

## Reproduce

Run from this directory. The tested interpreter is Python 3.14; exact package versions are pinned. A clean environment is recommended.

```bash
python -m venv .venv
# Windows PowerShell:
.venv\Scripts\Activate.ps1
# macOS/Linux: source .venv/bin/activate
python -m pip install -r requirements-solution.txt
python experiment.py
python train_predict.py
python -m unittest -v test_solution.py
python build_report.py
```

The full experiment compares seven candidates across two chronological folds and takes several minutes on CPU. No GPU, network service, credentials, or external dataset is required. To recreate submission files from the already frozen configurations, run `train_predict.py` without rerunning `experiment.py`.

The supplied files have hyphenated names in the folder root, unlike the paths shown in the original README. This solution reads the actual filenames directly. On a fresh clone, place these assessment files in the root:

```text
train-test.csv
validation.csv
validation-predictions-template.csv
december-chart-inputs.csv
```

For the source manifest, also include the original `freight-rate-ml-assessment.pdf`, `readme.md`, `requirements.txt`, and `score.py`. Source datasets and the assessment PDF are excluded from Git by default. They are not downloaded automatically or redistributed.

To run only the provided submission validator:

```bash
python score.py --predictions validation_predictions.csv --december-predictions data/december_chart_inputs.csv
```

This verifies file contracts and generates the chart. **It does not return hidden-set accuracy.**

## Modeling decisions

The primary model is robust ridge on rate per mile, with city/equipment categories, numerical shipment and coordinate features, and simple smooth date features. Multiply predicted rate per mile by distance to obtain a load price. Negative/zero weights become missing; medians and all other preprocessing are learned on training rows only. A missing-weight indicator retains the fact of missingness. Every training response is retained, with Huber-style reweighting reducing the influence of extreme responses.

The selected simple time specification uses one annual sine/cosine pair and two weekly pairs, without the extra annual harmonic or linear trend. Seven candidates test the effects of richer time features, market index, quote signal, and nonlinear CatBoost modeling. Unknown city categories map to no fitted city effect; coordinates still provide numerical information. `load_id` and the response never enter features.

Selection folds: January-April -> May-June and January-June -> July-August. The lowest mean fold dollar MAE determines the model. The frozen choice is then evaluated on September-October after training on January-August. Finally it is refitted on January-October to forecast November-December. Model selection does not use final holdout scores. See `artifacts/selection_decision.txt` for the experiment audit note.

The December scenario lacks market index, quote signal and coordinates. A separately constrained selection admits only signal-free candidates. The same core model won both selections in this run; no surrogate market forecast is needed. Coordinates for Lexington and Fort Wayne are recovered from labeled training rows. December rates are predictions of the fitted model, with no manual edits or fabricated future inputs.

## Interpretation and limitations

MAE is the selection criterion because the official hidden metric is unspecified and observed rates have extreme tails. All reported metrics retain outliers. RMSE can therefore remain high while typical errors are much smaller. The model targets a robust central estimate, not insurance against rare very expensive loads.

Ten labeled months do not establish repeatable yearly seasonality. November-December extrapolation and unseen locations remain uncertain; the fixed scenario has no ground truth or calibrated interval. Quote signal direction changes between months, so apparent correlations cannot be assumed to persist. Coordinates are used as provided rather than asserted to be geocoding ground truth.
